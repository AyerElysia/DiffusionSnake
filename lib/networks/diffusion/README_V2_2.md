# DiT V2.2: MM-DiT Patchify Dual-Stream Architecture

## 1. 概述 (Overview)
DiT V2.2 采用了类似 **Stable Diffusion 3** 的 **Multi-Modal Diffusion Transformer (MM-DiT)** 架构。它彻底改变了“特征提取-去噪”的串行模式，转而让图像 Patch 与轮廓点在 Transformer 中进行对等的联合交互。

## 2. 核心组件 (Key Components)

| 模块 | 实现类/方法 | 功能描述 | 核心收益 |
|:---|:---|:---|:---|
| **Patchify 层** | `PatchifyEmbedding` (dit_blocks_v2_2.py) | 将图像特征切成 8x8 Patch 并展开。 | 消除了复杂的池化层，保留原始像素级的细节。 |
| **联合交互块** | `JointDiTBlock` | 实现双流 (Point-Image) 并行的 Self-Attn 与 Cross-Attn。 | 支持点流向背景学习，同时也支持背景根据点流自适应增强（联合表征）。 |
| **SwiGLU FFN** | `SwiGLU` | 每层后的门控线性单元激活。 | 相比 V2.1 极大增强了非线性表达能力。 |

## 4. 数据流动分析 (Data Flow)
1. **输入处理**：特征图不再被池化，而是通过卷积变为 Patch Tokens。
2. **MM-DiT 交互**：在每个 Block 内，轮廓点和 Image Patch 被 concat 到一起做 Self-Attention。这意味着：
   - 轮廓点可以看到每一个 Patch。
   - Patch 也能感知当前轮廓点的分布（类似于感知掩码）。
3. **这种互感机制**：使得 V2.2 在处理极其模糊的边界时，能通过图像流的对比度自适应增强来辅助轮廓收敛。

## 6. 数据形状流动框架 (Data Shape Flow)

为了深入理解 MM-DiT 的多模态交互，下表记录了张量在网络中的生命周期：

```text
========================================================================================
阶段 (Stage)           数据流 1: 轮廓点 (Point Stream)     数据流 2: 图像块 (Image Stream)
========================================================================================

1. 输入准备 (Raw)      x_t: [N, 128, 2]                  cnn_feat: [B, 64, 128, 128]
                       (128个带噪声的点位移)                (YOLO特征图，B是图片数)
                               |                                 |
                               ▼                                 ▼
2. 线性投影 (Proj)     Pt_Embed: [N, 128, 256]           Patchify: [B, 256, 16, 16]
                       (坐标+采样特征混合投影)              (8x8小块卷积投影)
                               |                                 |
                               ▼                                 ▼
3. 序列化 (Flatten)    Tokens_A: [N, 128, 256]           Tokens_B: [N, 256, 256]
                       (128个点 Token)                    (256个补丁已对齐到N)
                               |                                 |
                               |          时间步 (t) [N, 256]      |
                               ▼                  |              ▼
========================================================================================
4. MM-DiT 交互层 (JointDiTBlock x 6)              | 
========================================================================================
                       
       ┌──────────────── 点与图的深度对话 (Joint Attention) ────────────────┐
       │                                                                    │
       │   Point Tokens (x)  <──────[Attention]──────>  Image Tokens (y)    │
       │     [N, 128, 256]                                [N, 256, 256]     │
       │                                                                    │
       └──────────────────────────────────┬─────────────────────────────────┘
                                          |
                                          | (重复 6 层)
                                          ▼
========================================================================================
5. 结果导出 (Export)    Point_Final: [N, 128, 256]        (Image Tokens 被丢弃)
========================================================================================
                               |
                               ▼
6. 最终预测 (Head)      Linear_Out: [N, 128, 2]
                       (输出 128个点的坐标修正值)
```

### 💡 核心逻辑说明：
- **维度聚合**：虽然输入是两个分支，但在 `JointAttention` 内部，它们被拼接成了一个长度为 **384** ($128+256$) 的统一序列进行计算。
- **动态对齐**：图像分支在第 3 阶段利用 `py_ind` 自动从 $[B]$ 广播至 $[N]$，确保每个待生成的轮廓都能“看”到它所属的整张底图。
