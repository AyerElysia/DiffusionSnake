为什么要换方案？

❌ 之前的伪3D方案（失败）

  • 把前帧+当前帧+后帧拼成3通道RGB输入
  • GT-box eval 前景 Dice 仅 0.130
  • Flow输出系统性外扩，面积膨胀中位数 14.46×
  • 根因：训练用GT极值点八边形初始化；推理用bbox中点八边形，两条不同路径 → 训练/推理不一致
  • 5000步中只有2170次有效contour监督

✅ 新方案设计原则

  • 回归 纯2D单帧，与最早验证过的2D基线保持一致
  • 用 MoonViT 替换YOLO特征，提升语义表达能力
  • V4.6c MoE扩散头 + V4.9 rich-state sampling
  • 训练/推理初始化 严格一致
  • 时序信息只在 初始化层面 注入，不改模型结构

训练创新：前帧轮廓初始化

设计动机

  • 矢状位相邻切片解剖结构几乎一样
  • 前帧轮廓 ≈ 当前帧GT（偏移仅几像素）
  • 让模型学会"从近初始轮廓做精修"
  • 自然对齐推理时的时序复用场景

推理创新：时序轮廓传播

推理流程

维护 prev_cache = {cls_id: contour}
Slice N: 检测 → 各类别分割
更新 prev_cache ← output['py'] + py_cls
Slice N+1: 检测 → 查 prev_cache
命中 → 前帧轮廓作为init（替换八边形）
未命中 → 标准bbox八边形init

设计亮点

  • 椎体每类唯一 → 按class_id直接匹配，无需IoU
  • case切换时自动清空缓存
  • output['py'] 已是 feature 坐标 → 直接缓存无需变换
  • 复用现有 sam_i_it_py 注入路径 → 零模型改动
  • 新出现的椎体 → 自动回退八边形

⚠ 遇到并解决的问题

  • MoonViT cache key配置错误
    locate_feat_fusion_mode → sagittal_moonvit_fusion_mode
  • center_only分支缺少patch_size元数据 → 补齐
  • GPU显存"泄漏"假象
    max_memory_allocated()历史峰值不重置，大batch后缓存池堆积 → OOM
  • 修复：每500 step调用torch.cuda.empty_cache()
