# V3.7 no-leak 泛化掉点诊断（2026-04-21）

## 结论

这次 `btcv_diffusion_dit_v3_7_v6b_full_noleak` 的掉点，**不是训练没收敛**，而是“正式 no-leak 主线并没有真正复现 standalone V6b 的关键机制”。

### 已确认的核心问题

1. **`scale conditioning` 在正式主线里没有真正生效**
   - 配置里虽然开了 `v3_7_use_scale_conditioning: true`
   - 但 `FlowMatchingEvolution.predict_velocity()` 之前没有把 `contour_scale` 传给 denoiser
   - 结果：full no-leak 训练/推理时，V6b 最关键的尺度条件分支实际上是空跑的

2. **正式主线缺少 V6b 的 per-contour normalization**
   - standalone V5b/V5f/V6/V6b 都用了：`x1_norm = x1_raw / contour_scale`
   - 正式主线之前仍然走的是全局 `diffusion_disp_stats` 归一化
   - 对多器官、多尺寸轮廓来说，这会弱化复杂小结构和后续 contour 的细节恢复

3. **正式主线缺少 V6b 的采样策略**
   - standalone V6b：`t ~ Beta(0.3, 1.0)` + `zero_x0_prob=0.5`
   - 正式主线之前：`t ~ Uniform(0,1)` + 全随机高斯 `x0`
   - 这会让训练目标更平均，但也更容易得到“平滑但保守”的解

## 新结论修正：`v6c` 不能直接从旧 `v6b` checkpoint 硬切

后续实际验证表明，上面的判断只说明 **`v6c` 主线代码跑通了**，但**不代表它适合直接从旧 `v6b_full_noleak` checkpoint 续训**。

### 已验证的 `v6c` 失败现象

使用：

- `configs/btcv_diffusion_dit_v3_7_v6c_full_noleak_resume_quicksave.yaml`
- checkpoint：`data/outputs/btcv_diffusion_dit_v3_7_v6c_full_noleak/checkpoints/epoch_357.pt`

在 `BtcvVal` 上 full val 的结果是：

- `mean_iou_sample_avg = 0.419090`

对应文件：

- `visual/v3_7_eval_now_full_v6c_epoch357/v3_7_full_test_iou_20260421_143936.json`

这说明一个关键事实：

> **把 `contour_norm + Beta-t + zero-x0 + scale-conditioning 真生效` 一次性叠到旧 `v6b` checkpoint 上，会产生严重的训练分布错位。**

也就是说，`v6c` 的问题不是“代码又没生效”，而是 **resume 策略本身不兼容**。

## 当前最稳的可用解：`v6d compat`

基于上面的失败结果，后面改成了 **分阶段迁移**：

1. **先保留旧 `v6b_full_noleak` 的训练目标分布不变**
   - 不启用 `v3_7_use_contour_norm`
   - 不引入 `flow_zero_x0_prob`
   - 不引入 `flow_t_beta_alpha/beta`
2. **只让“正式主线里真正生效的 scale conditioning”单独上线**
   - 即：继续用旧的全局 displacement normalization
   - 但现在 `contour_scale` 会真实传给 denoiser

新增配置：

- `configs/btcv_diffusion_dit_v3_7_v6d_full_noleak_resume_compat.yaml`

新增统一 full-val 评估脚本：

- `scripts/eval_v37_full_iou.py`

## 现在的策略判断

当前最合理的路径不是继续直接推 `v6c`，而是：

> **先走 `v6d compat` 这种“低分布偏移”的兼容增强路线，把 scale-conditioning 的收益单独吃到，再考虑二阶段地引入 contour-norm / Beta-t / zero-x0。**

换句话说，下一阶段更适合做：

1. 继续基于 `v6d compat` 观察 full-training 是否还能继续稳定抬升
2. 若稳定，再做 staged migration：
   - stage A: `scale conditioning only`
   - stage B: 再单独引入 `contour_norm`
   - stage C: 最后再评估 `Beta-t / zero-x0`

## 关键判断

这次掉点的本质不是：

- “V6b 思路错了”
- 或者“scale conditioning 没价值”

而是：

> **正式 no-leak 训练并没有真正跑到 standalone V6b 的方法本体。**

所以当前最值得做的，不是盲目换网络，而是先把 **V6b 的有效机制完整迁回正式主线**，再看它在 full no-leak 下的真实上限。
