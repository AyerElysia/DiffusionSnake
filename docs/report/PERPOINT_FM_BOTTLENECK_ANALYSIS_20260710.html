逐点 FM 路线瓶颈分析报告

围绕“逐点路线为什么仍不如 geom 探索，以及是不是小策略网络能力太差”的诊断结论
日期：2026-07-10 · 项目：DiffusionSnake-12-30 · 数据集：1232_final · 统一评估：5-step rollout, actual ODE=10 · 分析样本：177 images / 5,411 contours / 692,608 valid points

执行结论

当前证据不支持“逐点 FM 路线差，主要是因为 H64 小策略网络太弱”。H256 没有稳定优于 H64，线性模型在 current 输入上的 R² 反而最高；把输入扩到 richer feature 后方向符号略好，但 R² 变差。这说明主要瓶颈不是单纯网络宽度。

更可信的主因排序是：第一，动作族上限太低；第二，当前点特征对 reward-credit 的可辨识性弱；第三，reward 的方向大体有用但强度排序弱；第四，step4 的时序污染和训练覆盖会进一步稀释信号，但不是唯一根因。

路线裁决：逐点 FM scale 证明了“点级局部方向可以学到一点”，尤其最终步有弱信号；但它的动作族是沿 FM velocity 的 ±10% scale，oracle 上限本身很低，所以即使学会，也很难变成整体 IoU / Dice / mBoundF 收益。

1. 本次诊断口径

这份报告只回答一个问题：逐点 FM 路线当前为什么不佳，尤其是不是因为策略小网络能力不够。分析尽量避免只看在线 PPO 曲线，而是拆成四类证据：

证据目的结论用途
零策略 parity确认 off/mean 评估路径一致排除 ODE 20/10 混杂造成的假差异
reward-credit 监督 probe测试当前输入和更大网络能否预测点级收益判断是不是 H64 容量不足
GT diagnostic oracle在不训练网络的情况下测动作族理论上限判断动作参数化是否天然受限
短程因果训练比较 final-only、cyclic、last-two判断 step4 时序污染和覆盖策略影响
安全边界：normal residual、2D residual、GT oracle target 都是诊断上限，不能直接加入正式训练策略。后续如果要改动作族，需要单独设计可训练、无 GT 泄漏、可上线的策略。

5. Reward 信号是否合理

reward-credit 与最终 mask-level metric delta 的关系不是完全随机。它的符号方向多数时候是对的，但强度排序偏弱。这解释了为什么 PPO 能看到一点方向信号，却很难稳定推高全局指标。

这说明奖励函数不是“全没信号”，但它更像一个方向判别器，不是一个高质量的强度估计器。对于 PPO 来说，强度排序弱会让 advantage 排序不稳定，尤其在动作上限又很窄时，最终表现容易停在微弱 NSD 变化而不是整体轮廓质量提升。

8. 为什么逐点仍不如 geom 探索

候选原因证据强度判断
H64 小网络太弱弱H256 不稳定优于 H64；current 线性 R² 更高，所以不能作为主因
输入缺少可辨识信息中到强reward-credit probe 的 R² 很低，richer 输入只轻微改善方向
动作族太窄强±10% oracle 只有 7.34% 平方误差下降，86.49% 撞边界；normal residual 上限高得多
reward 强度排序弱中到强sign agreement 高，但 Pearson/Spearman 低，advantage 排序不够可靠
step4 时序污染中最终步好于前一步，但 final-only 也只给很弱提升
逐点高频破坏轮廓中当前小幅 scale 避免了大破坏，但同时限制了收益上限
综合解释：geom 探索虽然表达低频，但它的扰动更容易改变整体轮廓形态，并且 reward 对整体形态更敏感。逐点 FM scale 的自由度看起来高，但每个自由度只能沿 FM 方向做小幅快慢调节；一旦 FM 方向本身和 GT residual 不共线，策略再聪明也只能在错误子空间里优化。

9. 后续建议

下面是建议方向，不是已经上线的新训练机制。按照当前项目规矩，任何正式新增方案都需要先明确告知并得到确认。

优先级建议理由风险
高设计受约束的 FM + normal residual 或局部低维 basis 动作族oracle 显示方向自由度是核心瓶颈需要防止锯齿和高频破坏
高改进 reward 强度对齐，而不只看符号当前 reward 方向对，但排序弱，PPO advantage 会不稳需要避免 reward 过拟合某一指标
中给 point policy 增加边界梯度、局部 patch、邻域上下文当前 97-D 输入可辨识性不足计算量上升，需做离线 probe 再上线
中把 final-only 作为诊断训练窗口，而不是立即替代主训练最终步信号最干净，可用于验证动作族和 reward可能退化为过短视的末步修正
低单纯把 H64 加到 H256 或更大现有 probe 不支持这是主瓶颈增加训练不稳定和调参成本
最现实的下一步：不要先堆大网络。先用离线 oracle 和短程 final-only 对照验证一个更合理的局部动作族，例如“FM 主方向 + 小幅法向 residual + 平滑/低频约束”，再决定是否进入长训。

最终判断

逐点路线目前不如 geom，并不是因为策略完全不会学习，也不是简单把小 net 加宽就能解决。它的问题更基础：当前动作族把所有点限制在 FM velocity 方向附近做 ±10% 快慢调节，而真实精修误差经常需要横向、法向或局部形态自由度。奖励函数提供了一定方向信号，但强度排序不够好，无法弥补动作族上限低的问题。

因此，下一轮逐点研究应该优先改“动作空间 + reward 强度对齐”，其次再考虑输入特征和网络容量。单独加大 H64，不应该作为主线。
