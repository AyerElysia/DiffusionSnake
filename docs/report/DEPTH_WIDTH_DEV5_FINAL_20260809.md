# 深度扩容最终结论：保留 L6/F256

## 结论

在相同 Train72、相同 2000 个优化步、相同随机流、相同 GT-box、Memory-off、同一非锁定 Dev5、同一 2×4 AB2（8 NFE）评估下，L8/F256 **没有带来足以支持扩容的分割收益**。主线继续采用 **L6/F256**。

L8 相对 L6：

- 总参数增加 3,842,624（39.866M → 43.708M，+9.64%）；可训练参数 +23.2%。
- 峰值推理显存增加 0.201 GiB（4.957 → 5.158 GiB）。
- 五个 Dev5 病例的 native volume Dice **全部下降**，均值下降 0.000651。
- VerSe-2021 scan-equal Dice 下降 0.000404；NSD@2mm 下降 0.000980；dmean 恶化 0.104 mm。
- maximum HD 与 HD95 仅有很小改善（约 0.101 mm / 0.010 mm），不足以抵消参数、显存和其他主要指标的代价。
- 训练 steps 101–2000 的配对记录中，L8 平均每步慢 5.68%，80.4% 的步骤比 L6 慢。

因此，这次实验证明的是：**在 F256 下继续从 6 层加到 8 层，不是把参数花在刀刃上。**

## 先修复了一个决定性评估错误

最初 P0、P1 和冻结 H1 都得到 0 Dice，并不是三个模型同时失效。真实原因是测试初始化坐标错了：GT 检测框已经是 512 输入坐标，新增的直接八边形分支却没有除以 `down_ratio=4`，随后拿 512 坐标去采样 128×128 特征图，造成四倍坐标错位和轮廓坍缩。

修复保持训练定义不变：检测框先除以冻结 `down_ratio`，再直接生成训练侧同定义的 128 点八边形。轻量合同测试证明错误/修复坐标比精确为 4.0，修复后八边形与训练直接八边形逐值一致。

冻结 H1 锚点随后恢复为：native volume Dice 0.796993、VerSe scan-equal Dice 0.782512、NSD@2mm 0.787378、missing labels=0。由此确认旧的全零结果全部作废，不能用于模型判断。

## 边界

- 这是一组 5 病例的非锁定开发集结果，不是独立测试集泛化结论。
- 单次 evaluation wall-clock 不用于速度排名：P0 窗口与 H1 的 CPU 表面距离计算重叠，I/O/CPU负载不完全一致。模型代价使用参数、峰值显存和 1900 个配对训练步耗时描述。
- 这项结果只否定“F256 下继续加深到 L8”这一条路径，不否定后续浅层宽度、FFN容量或 NFE 调整。
