🎯 TL;DR — 一句话结论

两个层面的反馈信号问题都成立，且是耦合的。不是 reward 公式本身不行，也不是单凭动作空间不够——而是：

reward 在终端算一次 → advantage 平均给 5 步 → 早期 25% 的更新方向反了 → explorer 学不动

把 adv_ri 一个标量**复制**给 5 个共享 step（grpo_train_v5_geom_action.py:2078-2079），就是真根机制。我把它单独抽出来跑了 4000 条 step-wise 截断评分，给了下面的硬证据。

1. 背景与问题定义

用户的提问把 RL 反馈信号问题拆成两个层面，这个拆分经过这次实验验证是对的：

层面问题粗略对应
第一层 · Reward 计算 reward 函数本身写的是不是想优化的东西？baseline 是不是过强？K=8 能采到正收益吗？ _quality_score + _burr_penalty + gate + baseline_score
第二层 · 轨迹问责 5 段 outer refinement 的动作里，到底哪一步有贡献？应该反馈给哪一个？ terminal-only reward → adv_ri 复制给 5 step → PPO loss

之前 worklog 里 V5 学习型探索的随机对照跑 1000 步只到 0.861 就平台化，explorer net.4 absmax ≈ 0，reward 字段全程负。这次实验是为了在不动训练的情况下拿到因果证据。

为什么必须先做实验证明？ 我之前的初步分析（看代码+worklog）虽然把方向指对了，但你 worklog 里反复记录过"短跑必误判"（v5_exploration_ceiling_858），同样适用于 credit-assignment 改法：不先用数据坐实问题真根，直接动改造改反方向的可能性是真实的。这次 20 batch×K=8×5 step = 4000 条打分能在 ~4 分钟内跑完、不污染训练、可复现，是这个问题最小可证明实验。

2. 实验方法（默认关闭的离线探针）

2.1 在哪挂钩

诊断 hook 加在主训练循环里、rollout 采完后、advantage 计算前（grpo_train_v5_geom_action.py，json 文件 line 2051 之后的 "CREDIT-ASSIGNMENT DIAGNOSTIC" 块）。由环境变量 RL_V4_CREDIT_DIAG=1 触发，若同时 RL_V4_CREDIT_DIAG_STOP=1 则跑完探针后跳过 PPO 更新循环——不改 checkpoint、不污染训练。

2.2 探针每个 batch 算什么

  • 每条 K=8 rollout 在 5 step 每个截断位置 polys[t] 上算 partial score（复用同 _quality_score），5 步独立的 score_t 全部记下来。
  • deterministic 三步均值的截断 polys[t] 也对应算 5 个 partial，作为 per-step baseline。
  • 每步动作的范数 actions_norm_px、每步 old_log_prob 的均值，一并 dump。
  • 终端 reward / quality / gate / adv 重新算一份镜像（与主计算一致），保证 JSON 自成体系。
  • 输出 credit_diag_step{N}.json 到输出目录。

关键观察：

  • K=8 探索系统性地在低频法向上伤害 contour。平均 −2%（同样的 contour、同样的 deterministic mean 上叠加噪声，平均是负值）。这与 §13 "动作空间表达上限" 闭环：baseline 已压住所有有收益方向，剩余 8 个低频方向的随机扰动平均下来只会走更差附近。
  • 31% 的 contour 整组被 gate = 0 杀掉——PPO 对它们不做任何更新。这等于"学习信号在 PPO 之前就被 reward+baseline 杠掉"。

4. 第二层：轨迹问责层面的证据（这次实验的核心产出）

这是问题真根。即使 K=8 里挑出某条 rollout 终局 >0，PPO 也只把它当作一个标量 advantage (adv_ri)，for si, action in enumerate(traj['actions']): 循环里给 5 个 step 复制同一个 adv。step1 的动作和 step5 的修手领同样大的梯度——但它们对最终结果的贡献强非对称，下面用数据说话。

4.1 每步 partial 与 det 截断的偏离（mono 上升）

把每条 rollout 的截断 polys[t] 打分，减去同截断的 det partial，得到"sampled 在这一截断比 det 好多少"。注意：这个量越后期越负！

直观说：

  • step1 sampled 与 det 几乎平齐（−0.0037）：早期 step 的"低频法向扰动"总体上小幅伤害。
  • 偏离单调恶化到 step5 的 −0.0117——伤害主要在末段累积出来。
  • 但 PPO 给 5 步同样一个 adv。→ 早期 step 的负评语约是 −0.0037，理论上 step1 该领 0.1 鞭，实际它领的是 1.0 鞭（adv 是按 terminal std=0.1 floor 归一化的）。
  • 更重要：早期 step(28.8% 正收益) 与"整个 K=8 全员剩 13.8%"反过来——early step 赢家更多，early step 的"样本里其实有可学信号"。terminal-only disc filter 正好把这部分扔了。

4.2 终端 advantage 与每步 partial 的方向一致性（25% 错配）

把"按 terminal advantage 的 sign"当作 PPO 给的更新方向，把它与"该 step partial 与 det 截断之差的 sign"比较：

outer stepsign_agree(step_adv, terminal_adv)spearman(step_partial, terminal_partial)
1 (σ=0.8)75%0.34
2 (σ=0.7)77.5%0.37
3 (σ=0.6)80.6%0.52
4 (σ=0.5)87.5%0.65
5 (σ=0.4)100%1.00
关键证据： 25% 的 step1 动作所领 advantage 的符号与该 step 实际 partial 贡献方向正好相反。step1 的 spearman 与终端只 0.34——两者近独立。
这数学上是 GRPO/DAgger / RLHF 经典的 "lagging credit" 问题：因为 adv 在终端 std=0.1 上 floor 后，给到 step1 的学习信号 ≈ 75% 的真实方向加 25% 噪声。

4.3 信号-噪声：early step 的 dispersion 全被吃了

per_step_std_K_dispersion 是 K=8 在每步 partial 真分布的 std。它和 terminal std 的比值：

step12345
info_ratio4.2%5.4%6.4%7.5%8.1%

解释：

  • advantage 计算用的是 terminal std std=quality.std(dim=0,unbiased=False).clamp_min(0.1)。20 batch 平均 terminal std = 0.100（被 floor 到 0.1）。
  • 但 early step 的 true dispersion 是 0.0042—— 它只是终端 std 的 4.2%。terminal 标准→ adv 维持在 ±2 的 clip；step1 真信号 0.0042 全部被吃。
  • 结合 4.2 的 spearman 0.34 让 step1 的梯度方向主流方向是终局方向，但参杂 25% 噪声、且幅度被 floor 到 ~terminal scale——学习信号噪声比 SNR ≈ 0.34 × 100/4.2 ≈ 8，给早期 step 的 PPO 内积梯度方向 1 几乎是瞎打鞭。

5. 两层是如何耦合在一起的

  1. Reward 几乎全员打负（1.1-1.3 → terminal q_mean=−0.02）
    → K=8 大多采不到正收益方向（动作空间表达问题 + gate 失活）
  2. 越后期偏离越恶化（4.1 单调从 −0.0037 变到 −0.0117）
    → 终局 reward 是晚期伤害的代名词
  3. terminal advantage 是一个标量复制给 5 步（line 2078-2079）
    → 25% 的早期 step 更新方向反了（4.2 sign_agree=0.75）
  4. 早期 step 的真 dispersion 只有 terminal 的 4-5%（4.3）
    → 用 terminal std clamp floor=0.1 归一化，提前把早期 step 的真信号平均掉

闭环机制：

reward 系统性负 → adv 一负到底 → 复制给 5 步 → 早期 25% 反向 → explorer (lr=5e-5) 想学但梯度有 1/4 是反的 → net.4 absmax 长不到位 → policy mean 不敢动（加上 KL 钳）→ 训练日志 reward 永远负 → 平台 0.860

这连环效应解释了之前几个独立负结果为什么都收敛到同一面墙：

  • 16 模态 vs 8 模态：本质是 dispersion 规模变 × √2，但 terminal 归一照样压死 → 探索变更大不代表 reward 穿透。
  • detail reward 加 0.15：reward 端想奖励细节，但 advantage 复制给 5 步把信号平到每步 → curv_match 纹丝不动。
  • adaptive explorer (lr=5e-5)：explorer 想学，但 PPO 给的梯度 25% 反向 → logstd 几乎是 zero-init 不偏离。

之前定位成"动作空间表达上限"是对的（§13），但那只是 reward 端的表达极限。如果只修一层，另一层会继续拦住信号。这就是为什么之前每一次单层改动都"没反应"——不是改动无效，是被另一层吃掉了。

8. 下一步可改方案（先等你拍，不自己动）

方案改什么对应证据工程量风险
A. Per-step shaped reward
推荐		 把 reward 拆成 per-step partial-vs-det delta 的折现和 + terminal bonus；adv_ri 改为 adv[ri, si] 2.1-2.5 全条证中（动 reward/adv/PPO 索引）需调 shaping 系数
B. Per-step gate gate 张量化，不修 reward 1.2 + 部分 2.2小不解决 sign 错配
C. Value head + GAE 加 V(s_t)、δ 更新 全部大（新网络）增加精度依赖

下次任一方案上完后，可在新训练里开启同一个诊断探针，对比改前后：

  • sign_agree_per_step[0] 是否从 0.75 走到 → 1.0
  • spearman_per_step[0] 是否从 0.34 走到 → 1.0
  • info_ratio_per_step[0] 是否从 4.2% 走到 → 接近 terminal std 真值

这三个数字直接量化早期 step 是否拿到了真反馈，而非等慢爬后再判定（避免 v5_exploration_ceiling_858 的短跑误判陷阱再次出现）。

对方案 A 的最小子集：用 "per-step partial − det_partial" 作为额外 shaped reward 叠加到终端 reward 上（不替换原 terminal reward），把 adv_ri 改成 per-step 张量在 PPO inner loop 用 adv[ri, si]。改后开探针签应在前 step 几个 batch 内就看到 sign_agree[0] 升到 → 100%，这是"早期 step 的 feedback 已恢复"的客观证明，可在短步内判是非——这样就能**跳过短跑必误判的陷阱**。
