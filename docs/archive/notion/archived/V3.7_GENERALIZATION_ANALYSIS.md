# V3.7 泛化训练方案分析

> 从单样本100% IoU到多样本泛化训练，需要什么变化？

## 一、核心问题：哪些是"过拟合技巧"，哪些是"真正的架构改进"？

我们在单样本实验中做了很多改动，现在需要区分清楚：

### ✅ 可以直接带到泛化训练的改进

| 改进 | 为什么能泛化 |
|------|-------------|
| **PerPointFinalLayer** | 核心架构改进。不同点位天然需要不同的位移预测——这不是过拟合，而是模型容量提升。但需要加正则化。 |
| **低噪声 Flow Matching** | noise_scale=0.1~0.3 比默认1.0效果更好。降低噪声 = 更简单的速度场 = 更容易学习，这个结论对多样本同样成立。 |
| **减少 ODE 步数** | flow_ode_steps=1~3 比 10 步更好。步数越多，误差累积越多，毛刺越严重。 |
| **方向对齐 + 起点对齐** | 训练时 GT 轮廓方向和起始点与初始轮廓对齐。这消除了歧义，帮助学习，对泛化有益。 |
| **Laplacian 正则化** | 惩罚预测的二阶差分，鼓励光滑轮廓。这是经典正则化手段。 |

### ❌ 单样本专用，不能直接迁移

| 技巧 | 为什么不能泛化 |
|------|---------------|
| **float64 Residual** | 逐样本逐点的校正参数，纯粹的记忆化工具。 |
| **fix_t0 (t≡0)** | 消除了 flow matching 的随机性，等于纯回归。多样本需要 t 的多样性来学习鲁棒的速度场。 |
| **weight_decay=0** | 单样本需要完美记忆；多样本需要正则化防止过拟合。 |
| **RAW 模式** | 绕过归一化直接预测原始位移。多样本中不同图像的位移范围差异大，归一化到[-1,1]反而有助于学习。 |
| **eval-mode 冻结 backbone** | 单样本 BN 统计量不可靠所以需要冻结。多样本 BN 正常工作，端到端训练更好。 |

### ⚠️ 需要修改后才能用

| 改进 | 如何修改 |
|------|---------|
| **PerPointFinalLayer** | 加 L2 正则化约束各点权重不要偏离共享均值太远（见下文详解） |
| **低噪声** | 从0.0提高到0.1~0.3，保持一定的随机性用于数据增强 |
| **fix_t0** | 改为"低 t 偏好采样"——t 的分布偏向0附近（如 Beta(0.5, 5)），而非完全固定为0 |

## 二、PerPointFinalLayer 泛化方案（核心）

### 为什么 PerPointFinalLayer 能泛化？

在单样本实验中，我们发现共享 FinalLayer 是**容量瓶颈**：
- 128个轮廓点共享 Linear(256→2)
- 小轮廓上相邻点的特征几乎相同（双线性采样在相近位置）
- 共享权重被迫给相似特征输出相似位移 → 轮廓不准/毛刺

这个问题在**多样本中同样存在**！小器官/小结构的轮廓点密度高，特征重叠严重，共享层依然是瓶颈。

### 泛化版 PerPointFinalLayer 设计

```python
class RegularizedPerPointFinalLayer(nn.Module):
    """
    Per-point heads with shared-weight regularization.
    
    设计理念：共享基础 + 逐点残差
    - shared_weight: 所有点共享的基础权重 (2, 256) — 提供泛化能力
    - delta_weight: 每个点的偏移 (128, 2, 256) — 提供定制能力
    - 实际权重 = shared_weight + alpha * delta_weight
    - L2 正则化 delta_weight → 防止过拟合
    """
    def __init__(self, dim=256, out_dim=2, num_points=128, alpha=0.1):
        super().__init__()
        self.norm = RMSNorm(dim)
        self.adaLN = nn.Sequential(nn.SiLU(), nn.Linear(dim, 2*dim))
        
        # 共享基础（泛化能力来源）
        self.shared_weight = nn.Parameter(torch.zeros(out_dim, dim))
        self.shared_bias = nn.Parameter(torch.zeros(out_dim))
        
        # 逐点偏移（容量来源，受正则化约束）
        self.delta_weight = nn.Parameter(torch.zeros(num_points, out_dim, dim))
        self.delta_bias = nn.Parameter(torch.zeros(num_points, out_dim))
        
        self.alpha = alpha  # 控制逐点偏移的影响力
    
    def forward(self, x, t_emb):
        shift, scale = self.adaLN(t_emb).chunk(2, dim=-1)
        x = modulate(self.norm(x), shift, scale)
        
        P = x.size(1)
        # 实际权重 = 共享 + alpha * 逐点偏移
        w = self.shared_weight.unsqueeze(0) + self.alpha * self.delta_weight[:P]
        b = self.shared_bias.unsqueeze(0) + self.alpha * self.delta_bias[:P]
        
        return torch.einsum('npd,pod->npo', x, w) + b.unsqueeze(0)
    
    def regularization_loss(self):
        """逐点偏移的 L2 正则，加入总 loss"""
        return self.delta_weight.pow(2).mean() + self.delta_bias.pow(2).mean()
```

### 初始化策略
- `shared_weight/bias` ← 从预训练 V3.2 的 FinalLayer 复制
- `delta_weight/bias` ← 零初始化（起点=纯共享层，训练中逐渐分化）
- `alpha` 可以从 0.01 开始，线性增长到 0.1（warmup 策略）

### 正则化预算

```python
total_loss = flow_matching_loss + lambda_reg * per_point_layer.regularization_loss()
# lambda_reg = 0.01~0.1，需要实验确定
```

## 四、训练策略建议

### 4.1 两阶段训练（推荐）

**Stage 1: 共享层预训练**（沿用 V3.2 的成功经验）
```
epochs: 1~500
共享 FinalLayer（标准 V3.2 设置）
flow_noise_scale: 1.0（标准 flow matching）
flow_ode_steps: 10
```

**Stage 2: 逐点头微调**（V3.7 新增）
```
epochs: 500~1000
切换到 PerPointFinalLayer
init shared_weight ← Stage 1 的 FinalLayer 权重
delta_weight ← 零初始化
flow_noise_scale: 0.2（降噪）
flow_ode_steps: 3（减步）
lr: 1e-5（更小学习率）
v3_7_per_point_reg_weight: 0.01（正则化）
v3_7_laplacian_weight: 0.001（平滑正则）
```

这样做的好处：
1. Stage 1 让模型先学到通用的轮廓预测能力
2. Stage 2 在此基础上增加逐点容量，同时保持泛化

### 4.2 t 的采样策略

标准 flow matching: `t ~ Uniform(0, 1)` — 所有时刻等概率

我们发现 t 接近 0 时模型表现最好。多样本中可以用**偏向低 t 的采样**：

```python
# 选项 A: Beta 分布（偏向小 t）
t = torch.distributions.Beta(0.5, 3.0).sample((N,))
# E[t] ≈ 0.14, 大部分采样在 t < 0.3

# 选项 B: 分段均匀（50% 概率 t ∈ [0, 0.2], 50% 概率 t ∈ [0.2, 1.0]）
if random() < 0.5:
    t = uniform(0, 0.2)
else:
    t = uniform(0.2, 1.0)
```

这保留了 flow matching 框架的训练多样性，但让模型更多地学习"最后一步"的精确预测。

### 4.3 推理时的抗毛刺策略

即使泛化模型不能达到单样本的100% IoU，可以在推理时加入轻量平滑：

```python
# 方案 A: Fourier 低通（已实现）
disp = fourier_smooth(disp, k=8)  # 保留前8个频率分量

# 方案 B: Laplacian 平滑（后处理）
for _ in range(3):
    disp_smooth = (roll(disp, 1) + roll(disp, -1)) / 2
    disp = disp * 0.7 + disp_smooth * 0.3  # 保留70%原始 + 30%平滑

# 方案 C: ODE 步数=1（最简单最有效）
# 直接 1 步预测，不累积误差
```

## 五、我对毛刺问题根因的总结性认识

经过10个阶段的实验，我认为毛刺的根本原因是**多层累积效应**：

```
Root Causes (按严重程度排序):
  1. 共享 FinalLayer 容量不足（小轮廓相邻点特征相同 → 预测相同）
  2. ODE 多步积分误差累积（每步的微小偏差被放大）
  3. Flow Matching 噪声过大（高噪声 → 复杂速度场 → 难以精确学习）
  4. BN 训练/推理不匹配（单样本/小batch特别严重）
  5. 归一化往返精度损失（float32 round-trip）
```

其中 **1、2、3 是影响泛化性能的核心因素**，4、5 在多样本训练中影响较小。

**V3.7 泛化版本的核心改进点**:
- PerPointFinalLayer（正则化版本）解决根因 1
- 减少 ODE 步数（3步或1步）解决根因 2
- 低噪声训练（0.1~0.3）解决根因 3
- Laplacian 正则化 作为额外保护

## 六、预期效果与风险

### 预期
- 在 BTCV 验证集上，V3.7 泛化版应该比 V3.2 有 1~3% IoU 提升
- 小器官/小结构的轮廓质量应有明显改善（毛刺减少）
- 推理速度与 V3.2 相当（ODE 步数减少反而更快）

### 风险
- PerPointFinalLayer 增加参数量: 128×256×2 = 65,536 额外参数（vs 共享层的 514 参数）
  - 风险: 小数据集上可能过拟合 → 用正则化缓解
- 低噪声训练可能降低对检测框偏移的鲁棒性
  - 缓解: 用 noise_scale=0.2（不是0.0），保留一定的噪声鲁棒性
- 128 固定点数假设
  - 当前架构假设所有轮廓都是 128 点。如果需要变长轮廓，PerPointFinalLayer 需要改为动态的

### 建议的验证路径
1. 先在 BTCV 完整数据集上训练 V3.2 baseline（如果没有的话）
2. 然后训练 V3.7 泛化版，对比 IoU/Dice 指标
3. 重点关注小轮廓（C1 大小的器官）的质量改善
4. 可视化对比毛刺情况
