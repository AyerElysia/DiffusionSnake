## 0. 一句话结论

**"探索做得不够好"这个怀疑只对了一半。** 数据显示：当前的探索其实**经常能找到比 baseline 更好的方向**（61% 的训练步里 best quality > 0，gate 平均 0.71），真正的瓶颈是三件事：

1. **更新预算过度保守**：实际 KL ≈ 0.000016，比你自己设的 KL target (0.002) 低 **127 倍**，lr=8e-9——信任域从来没有被触碰到，等于油门只踩了 1%；
2. **探索/奖励的方向和真正的提升空间错位**：剩余的提升空间几乎全在"尾部差轮廓"和"好初始化被改坏"这两块，而当前低频全局扰动 + 均值导向的 reward 根本不照顾这两块；
3. **单一确定性均值结构性地吃不下 best-of-K 的收益**（这点你在 V10 的报告里自己已经证明过，但当前 V5/V7.x 路线又回到了同样的天花板下面）。

## 2. 今天的三个新发现（之前的报告里没有的）

### 发现 A：好初始化的轮廓正在被模型改坏 —— 最便宜的提升空间

用 V7.6 step1000 的全量逐轮廓数据（5411 个轮廓）：

| init IoU 区间 | 数量 | final IoU 均值 | 相对 init |
|---|---|---|---|
| ~0.7 | 1086 | 0.8503 | +0.150 |
| ~0.8 | 2203 | 0.8534 | +0.053 |
| **~0.9** | **1521** | **0.8698** | **-0.030（变差！）** |

init ≥ 0.85 的轮廓占 28.2%，它们的 IoU 均值从 0.881 被模型**降到 0.870**，其中 **59.6% 的轮廓 final 比 init 更差**。

如果只是做到"不退化"（final = max(init, final)），整体 mean IoU 就从 0.852 → **0.8616（+0.96 个点）**——这比过去一个月所有 RL 方案加起来的收益（+0.6 个点）还大，而且它不需要任何探索，只需要模型学会"初始已经很好时少动"。

### 发现 B：剩余提升空间集中在尾部，而 reward 是均值导向的

逐轮廓 IoU 分布：p05 = 0.744，p10 = 0.775，**15.7% 的轮廓 < 0.8**。把这 15.7% 修到 0.85，整体 mean → 0.8682（+1.6 个点）。而当前训练是均匀采样 + 均值 reward，每步随机 batch 里大部分是已经 0.86+ 的"好轮廓"，RL 大部分算力花在已经没有提升空间的样本上。

### 发现 C：探索没失败，是"吸收"太慢、且吸收上限太低

V7.6 训练日志 1305 步统计：

- best quality > 0 的比例：**61%**（即超过一半的步，K=8 里至少有一条 rollout 比 deterministic baseline 好）
- gate 平均 0.71
- **approx KL 平均 0.000016，KL target 是 0.002**——early stop 从未真正约束更新，约束更新的是 lr=8e-9 + clip=0.05 + grad_clip=0.20 这套手刹。

也就是说：**探索端每天都在交付正样本，更新端只敢拿走 1%**。这直接解释了"涨但是慢"。

## 3. 对你已有想法/路线的评价

### 3.1 "怀疑是探索做得不够好" —— 部分成立，但不是当前的 binding constraint

成立的部分：
- 低频法向 Fourier（8 modes）+ 小 sigma 的探索空间确实很小，它只能表达"整体鼓一点/瘪一点"，**表达不了尾部失败模式需要的修正**（比如整段边界贴错了对象、形状拓扑性错误）；
- V7.x 加的 band_detail / adaptive explorer 是在同一个"法向 Fourier 扰动"的范式内调结构，所以四个变体结果几乎一样——这本身就是证据：**在这个动作范式内，探索结构已经不是变量了**。

不成立的部分：
- 61% 的步都能找到正样本，说明"找到好方向"这件事没有失败；
- 你过去的 oracle 实验（V4 报告）已经证明：模型在 deterministic 解附近的 best-of-16 oracle gap 只有 +0.008 左右。**就算探索做得完美，在"当前解附近找更好的小扰动"这个游戏里，总奖池就这么大**，而你现在已经拿到了 +0.006。继续优化这个游戏的探索，最多再榨 0.002。

### 3.2 你过去诊断中我认为非常对、应该坚持的

- **ODE step noise 不可行、x0 diversity 才是 FM 的正确随机源**（oracle sweep 是整个项目里最干净的实验）；
- **小验证集会骗人**（V2/V12/V13 三次复现）——你现在坚持跑 177 全量评测是对的；
- **3 步 outer action 优于 60 步 inner SDE**（credit assignment 的选择是对的）；
- **V10 的结论：single learned mean 吃不下 selection 收益**——这个结论比你后来的路线选择更重要，见 4.3。

### 3.3 我认为有问题、值得重新审视的

- **保守参数是历史创伤的过度反应**。V8 系列崩溃（lr 5e-7 + 强蒸馏）后，lr 一路降到 8e-9。但 V8 崩的原因是蒸馏目标错误（circular dependency + 教错方向），不是 lr 本身。现在的 PPO+KL+gate 框架已经有四层保险，KL 利用率只有 1/127——**手刹和油门的问题被混在一起了**；
- **burr penalty 不对称**（sampled 扣、baseline 不扣）系统性压低 quality，让正样本更稀疏，这个你自己在 V5 报告里标记过"推测"，一直没做对照；
- **eval 固定 8 个 batch 仍然太小**，V7.5/V7.6 的 eval_iou 波动 ±0.0005 跟方案差异同量级，用它选 best checkpoint 接近抽签。

## 4. 我的诊断框架：三个被混在一起的问题

```
问题1（吞吐）：探索找到的正方向，吸收率被人为限到 1% → 涨得慢
问题2（方向）：探索和 reward 都在均值附近使劲，提升空间却在尾部和"防退化" → 涨的上限低
问题3（结构）：deterministic 单均值策略吃不下 selection 型收益 → oracle gap 永远吃不满
```

这三个问题需要的解法完全不同，过去的版本迭代经常一次换好几个变量，导致归因困难。建议接下来一次只动一个。

## 5. 接下来我打算做什么（按优先级）

### P0：油门实验 —— 验证"吸收率"假设（成本：1 张卡 × 1 天，零新代码）

在 V7.6 配置上只改两个数：`rl_v4_lr: 8e-9 → 1e-7`（×12），其余不动（KL target 0.002 此时才会真正成为约束）。跑 1000 步，看：
- approx KL 是否上升到 1e-4~1e-3 量级（说明信任域开始工作）；
- 全量 177 评测 step400/step1000 是否突破 0.8535。

**判定**：若涨幅明显加速 → 瓶颈确认为吸收率，继续在安全范围内加大；若 KL 上去了但 IoU 仍躺平 → 确认探索范式收益已枯竭，全力转 P1/P2。这个实验便宜且无论结果如何都消除一个最大的不确定性。

### P1：防退化奖励 —— 吃下发现 A 的 +0.96 个点（成本：小改 reward，1~2 天）

- reward 增加一项 `regression_penalty = w * relu(init_iou - final_iou)`，只对 init 较好（如 init_iou > 0.8）的轮廓生效；
- 或者更直接：advantage 按轮廓难度加权，`weight ∝ (1 - init_iou)` + 对"改坏好 init"的 rollout 额外惩罚。

这是把 RL 的火力从"已经 0.87 的轮廓再磨 0.001"转向"别把 0.88 的 init 改成 0.85"。

### P2：难例聚焦采样 —— 吃下发现 B 的尾部空间（成本：改 sampler，2~3 天）

- 离线跑一遍训练集 baseline，按 per-contour IoU 建难度索引；
- 训练时对 baseline IoU < 0.8 的轮廓 oversample（如 50% 配额）；
- 探索 sigma 对难例放大（难例本来就离 GT 远，小扰动够不着），对好例缩小——**这才是"探索"真正该改进的地方：探索强度应该条件于样本难度，而不是全局加结构**。

### P3：测试时选择路线 —— 绕开问题 3 的结构天花板（成本：中，1 周）

V10/V11 已经证明 selection 收益压不进单均值，那就不要压：
- 推理时 K 个 x0 seed 并行 rollout（你的 oracle 数据：x0 diversity best-of-16 ≈ +0.008）；
- 训练一个**不依赖 GT 的轻量 verifier**（输入：轮廓 + 图像边缘特征，输出质量分）来挑选，V11 的 ranker 失败可能是因为它依赖训练时的小验证信号，这次用更便宜的自监督信号（轮廓-图像梯度一致性、多 seed 一致性投票）；
- 这条线和 RL 正交，收益可叠加。

### P4（顺手，几乎零成本）：推理 noise scale 复查

V3.4 线上你测出 `infer_noise_scale 1.0→0.5` 白给 +0.0047，但当前 1232/V4.6c 全系 config 仍然是 `infer_noise_scale: 1.0`。值得在 V7.6 checkpoint 上花半天扫一遍 [0.3, 0.5, 0.7, 1.0]——如果结论迁移，这是又一个白给的零点几个点。

### 不建议继续投入的

- 在低频/带通 Fourier 范式内继续加 explorer 变体（V7.3~V7.6 已证明边际收益 ≈ 0.0001/版本）；
- 任何形式的在线蒸馏回 deterministic mean（V5b/V6/V8/V9 四次失败，circular dependency 是结构性的）；
- inner-step SDE logprob 路线（V4e 已证明 credit assignment 太长且噪声累积）。
